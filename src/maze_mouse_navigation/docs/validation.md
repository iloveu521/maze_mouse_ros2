# 导航验证记录

本文件仅记录 `maze_mouse_navigation` 的检查，不沿用地图包此前预设轨迹跟踪的结果。

## 构建与单元检查

Ubuntu 22.04、ROS 2 Humble、GCC 11.4，使用 `colcon build --symlink-install --packages-up-to maze_mouse_navigation`。编译命令确认核心库、节点和测试均使用 `-std=c++20`。

构建工具统一为 CMake 3.22，实际使用 `/usr/bin/cmake` 3.22.1。通过 `--cmake-clean-cache` 清除两个功能包的 CMake 配置缓存后重新配置、编译和安装；两份 `CMakeCache.txt` 均确认版本为 3.22.1，编译参数仍为 `-std=c++20`。随后执行两个功能包的 `colcon test`，汇总结果为 10 tests、0 errors、0 failures、0 skipped（其中包含下列 8 项 C++ 单元检查）。此次复验只涉及工具链与自动检查，未重新运行完整 Gazebo 探索。

8 项 C++ GoogleTest 检查通过：

- 前方扇区跨越 0° 时的选择和垂直距离投影。
- 负起始角度扫描及右侧扇区。
- `+Inf`、NaN、`-Inf`、低于量程值及扇区覆盖不足。
- 中位数抵抗离群值，紧急停车仍保留原始最小距离。
- 未知地图的泛洪距离与禁止未知通路的保守模式。
- 墙体双向更新、新墙触发绕行及不可达目标。
- 关闭外边界、起点即目标及无效格网参数。
- 双侧/单侧居中方向、开阔路口回退、角速度限幅与阻尼方向。

## 实际仿真专项检查

- 在 Gazebo 中将 Burger 放在 `(3.5,1.5)`，车头朝西，节点配置起点单元 `(3,1)`、方向 west。小车识别死胡同后掉头，依次到达 `(4,1)`、`(5,1)`、`(5,0)`。见 [掉头检查日志](uturn_check.log)。
- 默认起点完整运行期间暂停本次测试的 Gazebo 服务端，超过 1 秒后节点报告 `data_ready=false`，输出线速度、角速度均为零；恢复服务端后继续运行。见 [超时状态](timeout_status.yaml)与[停车指令](timeout_command.yaml)。
- 启动导航 RViz 配置，OpenGL 和 Path 显示插件初始化成功，候选路径与实际轨迹使用独立话题。
- 将 Burger 放在 `(1.5,3.5)`、车头朝南，使起步时后方恰好为尚未扫描的墙。初始泛洪候选选择北侧未知边，节点先转向扫描，识别为墙后重新选择西侧通路，未向墙内执行原候选移动，并实际到达后续单元。见 [未知后方边界检查日志](unknown_rear_check.log)和[后续状态](unknown_rear_status.yaml)。
