# 墙段识别、岔路与提前掉头验证

2026-11-01，ROS 2 Humble、Gazebo Classic 11、TurtleBot3 Burger。导航与控制代码使用 C++20，CMake 版本为 3.22.1。

## 行为变化

- 左右雷达扇区从 30° 扩至 60°，前方扇区独立扩至 90°。
- 360° 扫描按相邻点聚类并递归拟合直线。短于 0.24 m 的端面不作为跟随墙和扇区距离，但继续进入障碍 costmap 与碰撞预测。
- 连续左墙存在时保存其行进方向，右侧缺口不会使参考线转入岔路；恢复避障结束后也回到保存的方向。
- 前墙与两侧连续长墙共同确认死胡同。控制器生成切入、半圆和退出曲线，并在执行前检查完整曲线的硬膨胀间隙。
- 局部控制使用连续曲线的纯跟踪曲率，并预看前方曲率限制速度。RViz 的 `/maze_mouse/reference` 以绿色显示墙面参考线或掉头曲线。

## Gazebo 实测

默认验证配置使用 0.8 m/s 线速度上限、1.8 rad/s 角速度上限、0.04 m 额外膨胀。完整跑图结果：

| 指标 | 结果 |
| --- | --- |
| 最终状态 | `COMPLETE` |
| 两次完成时间 | 107.1 / 123.5 s 仿真时间 |
| 两次路程 | 29.18 / 30.10 m |
| 最大指令 / 里程计速度 | 0.800 / 0.810 m/s |
| `|v| < 0.03 m/s` 累计 | 2.17 / 3.96 s |
| 最小有效雷达测距 | 0.214 / 0.209 m |
| 第一处死胡同识别距离 | 1.148 / 1.139 m |
| 最终复跑第二处死胡同识别距离 | 1.144 m |
| 完成后指令 | 线速度和角速度均为零 |

0.8 m/s 首轮在第二处回转区域由连续左墙轮廓直接形成弧线；最终复跑则明确确认两处死胡同，第二处确认时前墙仍有 1.144 m。两次整程低速累计为 2.17 s 和 3.96 s，均未出现原版本在标注处长时间原地纠正。

旧控制器 1.2 m/s 最终验收轮次为 119.6 s、低速累计 8.91 s。新版本虽然把默认上限降至 0.8 m/s，两次完成均值为 115.3 s，低速累计明显减少。该比较样本较少，用于确认行为修复，不能当作统计性能结论。

## 自动验证

新增检查覆盖：左右 60° 与前方 90° 的独立覆盖范围；墙厚端面被引导层过滤但仍属于障碍；右侧开口不打断左墙航向；约 1 m 外生成完整掉头曲线；左侧仍有出口时不误判死胡同；使用实际 world 几何和偏航起点识别第二处回转区域。

完整 world 回归继续验证干净扫描和带 0.01 m 噪声、偏移起点两种情况。两种情况均完成跑图，中心到真实墙体的最小距离分别大于 0.33 m；控制器只接收扫描、扇区和里程计，world 几何仅在测试端用于生成射线和验证间隙。最终 Gazebo 终态见 [结果 JSON](scan_geometry_result.json)，对照轨迹见 [轨迹图](scan_geometry_run.svg)。

## 启动

```zsh
source /opt/ros/humble/setup.zsh
colcon build --symlink-install --packages-up-to maze_mouse_navigation
source install/setup.zsh
ros2 launch maze_mouse_navigation navigation.launch.py
```

在 RViz 中观察黄色预测轨迹、绿色参考线/掉头曲线、蓝色实际轨迹和膨胀 costmap。状态话题增加 `side_sector_width_deg`、`front_sector_width_deg`、`guide_wall_segments`、`short_faces_ignored`、`navigation_heading`、`dead_ends` 和 `dead_end_front_distance` 字段。
